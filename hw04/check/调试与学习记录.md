# 乘法表纠错：调试与学习记录

这部分保留老师给出的 81 个原始数，逐项比较后显示错误坐标。程序没有把错误数据直接改成正确数据，便于检查每个位置为什么报错。完整实现和全局、局部数组的比较见 [README](README.md)。

## 从运行结果检查位置

[ASM.OUT](ASM.OUT) 中依次列出 (1,1)、(2,3)、(4,5)、(6,6)、(8,8)，与题图一致。这里的坐标从 1 开始；内存中的字节偏移则按 (行号−1)×9+(列号−1) 计算。

已有 84 组真实 DOS 测试除了原表，还包括全对表、每个位置分别放入一个错误值，以及整张表全部错误的情况。[TESTS.TXT](TESTS.TXT)列出了每组结果。逐个位置测试能检查扫描有没有漏掉行尾、跨行时有没有跳错字节。

## DEBUG 里看到的变化

实际命令和记录分别保存在 [DEBUG.IN](DEBUG.IN)、[DEBUG.OUT](DEBUG.OUT)。先用 U 找到主程序 CS:0022 处的 CALL，再用 G=0000 0022 执行到它之前。此时第一项 1×1 应为 1，表中存的却是 7，所以会调用 PrintError。

P 执行完整个过程后，IP 从 0022 到 0025，SP 仍是 00FEh，AX、BX、CX、DX、BP、SI、DI 也与调用前一致。SI 原本用于扫描乘法表，过程里临时拿它读报错字符串，返回时已恢复。两次 D DS:0000 0050 显示的表数据相同，说明检查过程没有改写原表。

## C 版本的补充复核

最初整理于 2026-10-30 时，本机安全策略拦截了 C EXE，当时只完成编译和机器码核对。2026-11-06 再运行同一份 CHECKG.EXE、CHECKL.EXE，两者均正常返回 0，输出与 ASM.OUT 逐字节相同，记录保存在 [CG.OUT](CG.OUT)、[CL.OUT](CL.OUT)。源码和 EXE 都沿用原版本。

全局、局部两版的反汇编共 197 条用户函数指令。全局 table 在 .data 中，局部 table 则位于 main 的栈帧；本次局部版用 81 条 MOV 完成初始化。这些是当前编译结果的观察，换优化选项后具体指令可能不同。

## 学习心得

表里的数字 7 并不一定有错，1×7、7×1 本来就应该是 7。要判断一项对不对，必须把它的位置也考虑进去，拿行号和列号重新相乘后比较。只盯着题图里标红的数，写出来的就不是通用检查过程了。

这次查看 CALL 前后的寄存器，能直接看到保存和恢复的作用。PrintError 需要借用 SI、CX，主循环回来后又马上要继续用它们。少恢复一个，当前错误位置可能仍能显示，但后面的扫描就会受到影响。

C 中把数组移进 main，源码改动不多，反汇编里的初始化和寻址却有明显变化。看局部变量时，不能只凭它写在函数里就认定栈帧增加了多少；栈里还有计数器、调用空间、对齐和安全检查数据，需要结合实际指令来看。
