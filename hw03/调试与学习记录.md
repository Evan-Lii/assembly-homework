# 求和：调试与学习记录

这次作业先计算 1+2+…+100，再分别把累计结果放在寄存器、数据段和栈中；输入版接受 1～100 的 n。各版本源码、可执行文件和 C 反汇编见 [README](README.md)。

## 调试记录

三个固定版本都逐项累加，最终输出 5050。核对源码时分别查看 AX、数据段 DW 变量，以及栈版的 SS:[BP-2]，确认循环里更新的确实是要求的位置。

栈版先保存 BP，以 BP 建立位置参照，再 SUB SP,2 留出一个字。循环结束取出结果后，MOV SP,BP、POP BP 收回空间。十进制显示由共同的 PRINTNUM.INC 完成：反复除以 10，余数压栈后再输出。

输入版重点检查缓冲区里的长度和数字内容。按从 0 开始的偏移计算，缓冲区 +0 是容量，+1 返回字符数，+2 起才是输入字符。程序只接受 1～3 位数字，并检查数值是否落在 1～100。

[验证记录](验证结果.txt)保留了 247 次实际执行的结果范围：三个固定版本均输出 5050，输入版和 C 版分别遍历 n=1～100，另测了前导零和非法输入。[运行示例](实际运行示例.txt)可直接查看，C 的指令解释见[反汇编注释](C反汇编_中文注释.txt)。

## 学习心得

5050 只有四位十进制数字，却已经超过 8 位无符号数的范围。写程序前先看结果能有多大，才知道该用 DB 还是 DW、用一个字节还是一个字保存。

把同一个求和过程放到不同位置后，寻址的区别就很明显了。寄存器可以直接参与运算，数据段变量要找对 DS，BP 定位的栈变量则默认使用 SS。栈上申请的空间用完还要收回，否则后面的返回和调用都有可能受到影响。

算出 5050 之后，还得把它拆成字符才能显示。每次 DIV 前清零 DX，是因为 16 位除法实际读的是 DX:AX。另一个要分清的约定是，本题 PrintDec 会改写 AX、BX、CX、DX；调用后如果还需要这些值，就应当由调用者保护，不能假定它们会自动恢复。
